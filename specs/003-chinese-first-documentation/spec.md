# 003 中文优先文档

状态：已实现

## 背景

仓库面向中文学习者，但初始化 SDD 后，仓库指导、规格说明、模板和既有规格主要使用
英文。这会增加阅读成本，也会让后续由 Codex 生成的文档继续偏离项目的主要语言。

## 目标

- 让仓库自有文档统一以简体中文正文为主。
- 固化中文优先规则，使后续规格和用户说明保持一致。
- 在不破坏法律文本和技术标识的前提下保留必要英文。
- 让 SDD 校验器原生识别中文状态和中文章节名。

## 非目标

- 翻译 Python 标识符、命令、文件路径、模型名或第三方项目名。
- 修改 MIT 许可证英文原文。
- 把所有专业术语强行替换为不常用的中文译名。
- 运行模型下载、推理或 GPU 训练。

## 用户故事

- 作为中文学习者，我希望主要文档使用中文，以便快速理解 SFT 和 SDD 流程。
- 作为维护者，我希望仓库规则明确中文优先，以便后续变更不再产生整篇英文文档。
- 作为审阅者，我希望许可证译文与法律原文明确区分，以免误解其效力。

## 功能需求

- FR-001：仓库自有的 Markdown 文档、规格、计划、任务和代理指导必须以简体中文正文
  为主。
- FR-002：代码标识、命令、路径、模型名、第三方专有名词及 `FR-NNN`、`AC-NNN`、
  `T-NNN` 等机器可读 ID 可以保留英文。
- FR-003：`LICENSE` 必须保留官方英文原文，并提供带有非官方声明的中文参考译本。
- FR-004：SDD 校验器必须支持中文状态值和中文“验证方式”章节，同时兼容历史英文格式。
- FR-005：根目录指导必须明确中文优先规则，README 必须向学习者说明该约定。

## 非功能需求

- NFR-001：文档改造和 SDD 校验不得下载模型或使用 GPU。
- NFR-002：中文化不得改变现有 SFT 数据、训练、评测和推理行为。
- NFR-003：校验器继续只依赖 Python 标准库。
- NFR-004：公开仓库不得新增个人邮箱、本机绝对路径、凭据或设备标识。

## 验收标准

- AC-001：所有仓库自有 Markdown 文档均以中文说明为主，必要英文仅用于技术表达。
- AC-002：`make sdd-check` 能校验使用中文状态和中文章节名的全部编号规格。
- AC-003：自动化测试同时覆盖中文格式和对历史英文状态格式的兼容。
- AC-004：仓库包含 `LICENSE.zh-CN.md`，并明确冲突时以 `LICENSE` 英文原文为准。
- AC-005：`make check`、`make test` 和 `make lint` 均通过，且无模型下载或 GPU 训练。
- AC-006：隐私扫描未发现个人邮箱、本机绝对路径、凭据或设备标识。

## 待确认问题

无。
